# /custom-ord-annotations

Applies CDS annotations to customise the ORD document produced by `@cap-js/ord`.

Arguments passed: `$ARGUMENTS`

---

## Dispatch

Parse `$ARGUMENTS`. Route to the matching section. If no argument, address the user's request using the full reference below.

| Argument      | Section                                   |
| ------------- | ----------------------------------------- |
| `visibility`  | Visibility                                |
| `title`       | Title and description                     |
| `identity`    | ORD ID and version                        |
| `grouping`    | Package and consumption bundle assignment |
| `entity`      | Entity types                              |
| `dataproduct` | Data products                             |
| `passthrough` | Pass-through fields                       |

---

## Before writing any annotation

Check two exclusions first — they override everything else:

- `@protocol: 'none'` on a service → no ORD resources generated for it at all.
- `@cds.external: true` on a service → excluded from API/event resource generation. May contribute to `IntegrationDependency` if also annotated with `@data.product` and `@cds.dp.ordId` (see [Data products](#data-products)).

Global priority for all other annotations:
```
@ORD.Extensions.<field>  >  standard CAP annotations  >  .cdsrc.json ord.*  >  plugin defaults
```

## Visibility

`@ORD.Extensions.visibility` controls the `visibility` field on `apiResource`, `eventResource`, and `entityType`.

- **Values:** `"public"` | `"internal"` | `"private"`
- **Default:** `ord.defaultVisibility` config (falls back to `"public"`)
- **`"private"` → resource is omitted from the document entirely**

Resolution order (first match wins):
1. Service is a primary data product (`@data.product: true`) → always `"internal"`, annotation ignored.
2. `@ORD.Extensions.visibility` present → use it.
3. `@ORD.Extensions.implementationStandard: 'sap:ord-document-api:v1'` present → `"public"`.
4. None of the above → `ord.defaultVisibility`.

When set on a `kind: "service"` definition, the value cascades to all sub-definitions whose name starts with `<service.name>.` — unless a sub-definition already has the annotation (never overwritten).

With an SAP `policyLevel`, resolved visibility determines which of the up-to-15 generated packages the resource is assigned to.

```cds
annotate ProcessorService with @ORD.Extensions.visibility: 'internal';
```

## Title and description

### Title

`@ORD.Extensions.title` is the explicit resolver for event resources and entity types. For API resources it wins via the pass-through spread (overwrites the computed value).

Resolution chain (first match wins):

| Priority | Annotation              | Notes |
| -------- | ----------------------- | ----- |
| 1 | `@ORD.Extensions.title` | Explicit for event/entity; pass-through for API |
| 2 | `@title`                | Standard CAP label |
| 3 | `@Common.Label`         | OData common label |
| 4 | `@EndUserText.label`    | SAP end-user label |
| 5 | *(fallback)*            | API: service name; Event: "ODM appName Events"; Entity: name segment of `@EntityRelationship.entityType` |

```cds
annotate CatalogService with @ORD.Extensions.title: 'Catalog Service';
// Standard CAP annotations also work (lower priority):
annotate CatalogService with @title: 'Catalog Service';
annotate CatalogService with @Common.Label: 'Catalog Service';
```

### Description

Resolution differs by resource type:

**API resources** — `@ORD.Extensions.description` (pass-through) → `@Core.Description` → `"Description for <name>"` (fallback)

**Event resources** — `@ORD.Extensions.description` → `@description` → `@Core.Description` → `"CAP Event resource describing events / messages."` (fallback)

```cds
// API resource:
annotate CatalogService with @Core.Description: 'Provides read access to the product catalog.';

// Event resource (highest priority):
annotate MyEventService with @ORD.Extensions.description: 'Publishes order lifecycle events.';
// or:
annotate MyEventService with @description: 'Events for order processing.';
```

## ORD ID and version

### `@ORD.Extensions.ordId`

Overrides the auto-generated ORD ID on API resources, event resources, and entity types.

- **Applies to:** `service`, `entity`
- **Default:** `<namespace>:<resourceType>:<resolvedServiceName>:<version>`
- Supports `{namespace}` and `{type}` placeholder tokens (single braces).

```cds
annotate CatalogService with @ORD.Extensions.ordId: 'sap.sample:apiResource:Catalog:v1';
```

For services exposing **multiple protocols**, set ordId per protocol:

```cds
annotate MyService with @protocol('rest').ORD.Extensions.ordId: 'sap.sample:apiResource:MyServiceREST:v1';
```

### `@ORD.Extensions.version`

Sets `version` on an API resource, event resource, or entity type. Also drives the `v<N>` suffix in auto-generated `ordId` values.

- **Applies to:** `service`, `entity`
- **Default:** `"1.0.0"` for services; derived from the version segment of `@EntityRelationship.entityType` for entities.
- **Constraint:** when generating CSN resource definitions for a single-service data product, the fully-qualified service name must end in a `.v<N>` segment (e.g. `my.namespace.Service.v2`) and that major must match the major of this annotation. Mismatch throws during CSN compilation (not at general startup).

```cds
annotate CatalogService with @ORD.Extensions.version: '2.0.0';
```

## Package and consumption bundle assignment

### `@ORD.Extensions.partOfPackage`

Overrides which package a resource is assigned to. Without it, the plugin auto-selects by matching resource type and visibility against generated packages.

- **Applies to:** `service`, `entity`
- Supports `{namespace}` and `{type}` placeholder tokens (single braces).

```cds
annotate CatalogService with @ORD.Extensions.partOfPackage: 'sap.sample:package:custom:v1';
```

### `@ORD.Extensions.partOfConsumptionBundles`

Links a service's resources to consumption bundles. The bundles must be defined in `ord.consumptionBundles` in `.cdsrc.json` — this annotation only creates the reference.

- **Applies to:** `service`
- **Values:** array of `{ ordId, defaultEntryPoint? }`

```cds
annotate CatalogService with @ORD.Extensions: {
    partOfConsumptionBundles: [{ ordId: 'customer.myapp:consumptionBundle:public:v1', defaultEntryPoint: '/' }]
};
```

### `@ORD.Extensions.partOfGroups`

Overrides the `partOfGroups` array. Has an explicit resolver on event resources; also passes through on API resources (not excluded from the API spread).

- **Default:** `["<groupTypeId>:<namespace>:<resolvedServiceName>"]`

```cds
annotate MyService with @ORD.Extensions.partOfGroups: ['sap.sample:serviceGroup:MyGroup:v1'];
```

## Entity types

An entity type record is only generated when `@EntityRelationship.entityType` is present. Without it, no entity type record is created. Note: `@ODM.entityName` alone (without `@EntityRelationship.entityType`) still contributes to `exposedEntityTypes` on containing services — the entity is not fully invisible.

### `@EntityRelationship.entityType` *(required for entity type records)*

Gates entity type generation. The value drives the auto-generated `ordId`, `localId`, and `version`. Also populates `exposedEntityTypes` on API and event resources that expose this entity.

- **Values:** `"<namespace>:entityType:<name>:<version>"` — e.g. `"sap.odm:entityType:BusinessPartner:v1"`

```cds
annotate my.BusinessPartner with @EntityRelationship.entityType: 'sap.odm:entityType:BusinessPartner:v1';
```

### `@ORD.Extensions.level`

Sets the structural level of an entity type.

- **Values:** `"aggregate"` | `"root-entity"` | `"sub-entity"`
- **Default:** `"root-entity"` if `@ObjectModel.compositionRoot` or `@ODM.root` is truthy; otherwise `"sub-entity"`

```cds
annotate my.Entity with @ORD.Extensions.level: 'root-entity';

// Equivalent shortcuts (no @ORD.Extensions.level needed):
annotate my.Order with @ObjectModel.compositionRoot: true;
annotate my.Item  with @ODM.root: true;
```

### `@ORD.Extensions.localId`

Overrides `localId` on an entity type. Defaults to the name segment of `@EntityRelationship.entityType`.

```cds
annotate my.Entity with @ORD.Extensions.localId: 'MyEntity';
```

### `@ODM.entityName`

Appends `{ ordId: "sap.odm:entityType:<name>:v1" }` to `exposedEntityTypes` on all services containing this entity.

```cds
annotate my.BusinessPartner with @ODM.entityName: 'BusinessPartner';
```

### `@ORD.Extensions.exposedEntityTypes`

Replaces the entire auto-derived `exposedEntityTypes` array on an event resource. Default is auto-derived from `@EntityRelationship.entityType` and `@ODM.entityName` on the service's entities.

```cds
annotate MyEventService with @ORD.Extensions.exposedEntityTypes: [
    { ordId: 'sap.odm:entityType:BusinessPartner:v1' }
];
```

## Data products

`@data.product` behaves differently depending on whether the service is local or external.

### Local service — primary data product

`@data.product: true` (or the long form `@DataIntegration.dataProduct.type: 'primary'`) on a locally-exposed service forces:

- `visibility` → always `"internal"` *(not overridable)*
- `direction` → `"outbound"` *(not overridable)*
- `apiProtocol` → `"sap.dp:data-subscription-api:v1"` *(overridable via `@ORD.Extensions.apiProtocol`)*
- Resource definition format → CSN

```cds
annotate MyDataProductService with @data.product: true;
```

### External service — IntegrationDependency generation

All three annotations must be on the same service definition:

1. `@cds.external: true` — marks as external (also excludes from API/event resource generation)
2. `@data.product: true` — marks as a data product
3. `@cds.dp.ordId: 'namespace:apiResource:Name:vN'` — second colon-segment **must** be `apiResource`

```cds
annotate sap.sai.Supplier.v1 with {
    @cds.external
    @data.product
    @cds.dp.ordId: 'sap.sai:apiResource:Supplier:v1'
};
```

Customise the generated aspect's title and description via `@ORD.Extensions` — adds fields without replacing the auto-built `aspects` array:

```cds
annotate sap.sai.Supplier.v1 with @ORD.Extensions: {
    title      : 'SAI Supplier API',
    description: 'Integration with SAP Analytics Intelligence Supplier Data Product'
};
```

## OpenAPI servers

`@OpenAPI.servers` injects production server URLs into the generated OpenAPI spec file only. It does **not** affect the ORD document JSON structure.

```cds
annotate CatalogService with @OpenAPI.servers: [
    { url: 'https://my-service.api.sap.com', description: 'Production' }
];
```

## Pass-through fields

The spread behaviour differs by resource type — know this before setting arbitrary `@ORD.Extensions` keys:

**API resources** — only `ordId` is excluded. Every other `@ORD.Extensions.*` key passes through and overwrites any value already computed by explicit resolvers (`title`, `description`, `version`, `visibility`, `partOfPackage`, `partOfGroups`, etc.).

**Event resources and entity types** — all resolver keys (`version`, `description`, `ordId`, `title`, `exposedEntityTypes`, `visibility`, `partOfGroups`, `partOfPackage`, `resourceDefinitions`) are excluded from the spread. To set these, use their named annotation; adding them to a generic `@ORD.Extensions` block has no effect on event resources or entity types.

Any key not in the resolver exclusion list is deep-merged verbatim. Use this for arbitrary ORD fields:

```cds
annotate ProcessorService with @ORD.Extensions: {
    industry       : ['Retail', 'Consumer Products'],
    lineOfBusiness : ['Sales'],
    extensible     : { supported: 'no' },
    releaseStatus  : 'beta',
    tags           : ['finance', 'reporting']
};
```

Per-protocol pass-through:

```cds
annotate MyService with @protocol('rest').ORD.Extensions: {
    releaseStatus: 'active'
};
```

`@ORD.Extensions.resourceDefinitions` overrides generated resource definitions. On event resources it replaces the auto-generated AsyncAPI entry (explicit resolver). On API resources it passes through via the spread. Values: array of `{ type, mediaType, url, accessStrategies }`.

## Implementation notes

- **Interop CSN remapping** (affects the `.csn` resource definition file, not the ORD document): `@Common.Label`, `@title`, `@label` → `@EndUserText.label`; `@description` → `@EndUserText.quickInfo`. `@cds.autoexpose` and `@assert.unique*` are deleted before serving.
- **Combining `@ORD.Extensions.ordId` with multiple protocols:** use `@protocol('<name>').ORD.Extensions.ordId` to set per-protocol ordIds independently.
